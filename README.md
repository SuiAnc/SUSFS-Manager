A standalone Android app that is **only** the SUSFS management UI, extracted from FinaSU 0.1.0-beta3
and SukiSU-Ultra 4.2.0 (both KernelSU forks), with one setting that chooses which of the two
pages is shown. It does not bundle a kernel, a daemon, or a module store.

Like upstream, it execs a `ksud` binary out of its own APK. **The SUSFS subcommand only exists in
those projects' ksud builds, not in stock KernelSU or KernelSU-Next**, so this app bundles two
payloads: FinaSU's as `libksud.so` and SukiSU-Ultra's as `libksud2.so`. See
[Bundling ksud](#bundling-ksud) — building without the one you pick produces
`error: unrecognized subcommand 'susfs'` at runtime.

## What it does

The app ships **two** SUSFS pages and a switch between them, because the two root managers that
implement SUSFS expose incompatible `ksud` interfaces:

| Page | Manager | Payload | Protocol |
|------|---------|---------|----------|
| FolkSU | [FinaSU](https://github.com/LyraVoid/FinaSU) | `libksud.so` | `<ksud> susfs status / export / import / apply`, one JSON document |
| SukiSU-Ultra | [SukiSU-Ultra](https://github.com/SukiSU-Ultra/SukiSU-Ultra) | `libksud2.so` | `<ksud> susfs status / config get / set / ...`, individual config keys |

Tap the pill at the bottom of either page to switch. The choice is persisted in the `settings`
SharedPreferences file. The page and the command backend switch together: picking SukiSU-Ultra runs
SukiSU-Ultra's `ksud`, never FolkSU's, and the other way round.

### FolkSU page

It drives the `susfs` subcommands of the bundled `ksud`:

| Action   | Command                            | Purpose                                         |
|----------|------------------------------------|-------------------------------------------------|
| status   | `<ksud> susfs status`              | Detect the SUSFS build and its capabilities      |
| export   | `<ksud> susfs export`              | Read the saved configuration as JSON             |
| import   | `printf '%s' <json> \| <ksud> susfs import` | Validate and save a configuration       |
| apply    | `<ksud> susfs apply`               | Ask the kernel to adopt the saved configuration  |

The UI is the six-page pager from upstream, unchanged:

0. **Overview** — detection, management state, saved rule count, automatic mode, apply, last report,
   import/export, and the detected feature list.
1. **Settings** — hide mounts (SUS_MOUNT), logging (ENABLE_LOG), AVC spoofing.
2. **Paths** — `path` and `map` rules.
3. **Spoofing** — `uname`, `cmdline`, and `kstat` rules.
4. **Redirect** — `redirect` rules.
5. **Extensions** — hidden modules and mount prefixes.

### SukiSU-Ultra page

It is SukiSU-Ultra's **Material** SUSFS UI, ported as-is. The upstream `Miuix` variant was dropped:
it needs a third-party Compose design library (`top.yukonga.miuix.kmp`) that this app does not
depend on. The page has six tabs:

0. **Basic settings** — enable log, hide SUS mounts, hide BL, cleanup residue, AVC log spoofing,
   execute in post-fs-data, auto-start, uname / build-time spoofing, cmdline or bootconfig path.
1. **SUS paths** — the path rules, with an installed-app picker for the package directory.
2. **SUS loop paths** — paths to wait for before hiding.
3. **SUS maps** — mount-point rules.
4. **Kstat config** — kstat spoofing, including the static snapshot form (inode, timestamps, blocks).
5. **Enabled features** — the feature list as the kernel reports it.

It also has backup and restore, which read and write SukiSU-Ultra's own configuration through the
same `ksud`.

## Requirements

* Android 12 (API 31) or newer, on **arm64-v8a** (the only ABI ksud is built for).
* A device rooted with **one of** KernelSU, KernelSU-Next, APatch, or Magisk — this supplies `su` and
  the kernel-side SUSFS implementation — **and** a kernel built with the SUSFS patch. Without the
  kernel patch the app still installs and runs, but the status page reports `not_detected` and every
  control stays disabled: that is the intended behaviour, not a bug.
* Superuser access granted to **SUSFS Manager** itself (package `dev.susfs.manager`). The first
  launch raises the prompt; if it is denied the status page shows "root unavailable" until you grant
  it and reopen the app.

The rooting solution's own `ksud` is **not** used. Only `su` comes from it — the SUSFS
subcommands that drive these pages exist only in the FinaSU and SukiSU-Ultra builds of `ksud`,
which is why the app carries its own copies (see [Bundling ksud](#bundling-ksud)).

## Bundling ksud

`ksud` is the manager's Rust userspace daemon. It is compiled for Android and, like stock KernelSU,
packaged under `jniLibs` with a `.so` name so Android extracts it as a real executable with the
execute bit set. `useLegacyPackaging = true` in `app/build.gradle.kts` is what makes that extraction
produce a file on disk instead of something the linker would mmap as an ELF shared object.

Two payloads are expected, one per page:

| File | Built from | Needed for |
|------|------------|------------|
| `app/src/main/jniLibs/arm64-v8a/libksud.so` | FinaSU | the FolkSU page |
| `app/src/main/jniLibs/arm64-v8a/libksud2.so` | SukiSU-Ultra | the SukiSU-Ultra page |

Build each from its own tree, then copy it in **before** assembling this app:

```sh
# FolkSU / FinaSU
cd FinaSU-0.1.0-beta3/userspace/ksud
cargo ndk -t arm64-v8a build --release
cp target/aarch64-linux-android/release/ksud \
   <this project>/app/src/main/jniLibs/arm64-v8a/libksud.so

# SukiSU-Ultra
cd SukiSU-Ultra-4.2.0/userspace/ksud
cargo ndk -t arm64-v8a build --release
cp target/aarch64-linux-android/release/ksud \
   <this project>/app/src/main/jniLibs/arm64-v8a/libksud2.so
```

The two are not interchangeable, so keep the names straight: `libksud.so` is what the FolkSU page
execs, `libksud2.so` is what the SukiSU-Ultra page execs. Both are resolved from
`applicationInfo.nativeLibraryDir` at runtime, and both must be real ARM64 ELF executables.

`tools/static_check.py` prints a note for each one that is missing, and fails if a file exists but is
implausibly small. The files are deliberately **not** committed: they are multi-megabyte binary
artifacts of separate Rust crates.

The Gradle build enforces the same rule. `preBuild` logs a warning for every variant, so a debug
build of the UI still works while you are compiling a payload; `preReleaseBuild` fails outright,
because a release APK without its payload is a broken app rather than an incomplete one.

## Building

The project is a single-module Gradle build. It needs a JDK 21 toolchain and an Android SDK with
API 37 platform and build-tools installed.

```sh
# Point Gradle at your SDK if it is not in ANDROID_HOME / ANDROID_SDK_ROOT.
echo "sdk.dir=/path/to/android-sdk" > local.properties

./gradlew :app:assembleDebug     # debug APK
./gradlew :app:assembleRelease   # release APK (minified; needs a signing config, see below)
```

The APK lands in `app/build/outputs/apk/<variant>/`.

### Signing a release build

`app/build.gradle.kts` deliberately declares no signing config, so `assembleRelease` produces an
unsigned APK. Either install the debug build, sign the release APK yourself, or add a signing block
to `app/build.gradle.kts`:

```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file("../keystore.jks")
            storePassword = "…"
            keyAlias = "…"
            keyPassword = "…"
        }
    }
    buildTypes {
        release { signingConfig = signingConfigs.getByName("release") }
    }
}
```

## What was changed from upstream, and why

The UI layer is a near-verbatim port, so this list is short on purpose.

* **Package** renamed `me.weishu.kernelsu` → `dev.susfs.manager`, and the SukiSU-Ultra port renamed
  `com.sukisu.ultra.ui.screen.susfs` → `dev.susfs.manager.ui.screen.sukisu`.
* **Two pages, one app.** Upstream each ship one SUSFS page driven by their own `ksud`. Here both
  pages and both payloads are bundled, and a persisted setting picks which pair is active. The two
  protocols are genuinely different (one JSON document versus individual config keys), so this is a
  switch between two self-contained pages, not a shared UI over two backends.
* **SukiSU-Ultra's `Miuix` variant dropped.** Upstream renders its whole UI twice, once in Material 3
  and once with `top.yukonga.miuix.kmp` (a Xiaomi-style Compose library). Only the Material variant
  was ported, which removes that third-party dependency and roughly half the ported code.
* **`Natives` is no longer JNI.** Upstream's `isSafeMode` came from `libkernelsu.so`. Here it is
  read once per root shell via `getprop persist.sys.safemode` / `ro.sys.safemode`, matching what
  `ksud` itself does. The only kernel-side safe-mode signal is an ioctl a shell cannot reach, so the
  worst case is that the app offers Apply while the kernel ignores it.
* **Root shell simplified.** Upstream keeps a global-mount shell, a bounded backoff retry loop, and
  an `sh` fallback. All three exist to serve a whole manager app. Here one shell is enough, and a
  non-root shell is reported as a failed probe rather than silently accepted.
* **Installed-app list is local.** SukiSU-Ultra asks its own manager for the list of apps that were
  granted root; a standalone app has no such list, so `SuperUserViewModel` enumerates installed
  packages instead (`QUERY_ALL_PACKAGES`). The pickers only need a package name, a label and a
  `PackageInfo`, so this is the same information by a different route.
* **Theme simplified.** Upstream's palette/wallpaper-driven theme (materialKolor, user-selectable
  colour specs) is replaced by a dynamic-colour scheme. The screen reads
  `LocalFolkWallpaperTokens` directly, and every wallpaper branch short-circuits to plain Material
  colours when that local is null, so leaving it unset is a supported path rather than a stub.
* **Navigation.** Upstream pops a navigation3 back stack; the back arrow here finishes the activity.
  The `Navigator` interface is preserved so the ported screens needed no edits.
* **Removed** everything that is not SUSFS: the module store, superuser list, web UI, installers,
  update checker, boot receivers, zygote preload, and the bundled native code — except the two `ksud`
  payloads, which are required.
* **Unused Material components removed.** `SegmentedList.kt` upstream also carries sliders,
  dropdowns, radio buttons, checkboxes and text fields. The FolkSU screen uses none of them, so they
  are dropped — which also removes this port's only dependency on the newest expressive widgets.

## Static checks

`tools/static_check.py` runs without a JDK, an SDK or a network, and catches the mistakes a port
like this actually makes: a left-behind upstream package reference (`me.weishu.kernelsu`,
`com.sukisu.ultra`, `top.yukonga.miuix`), a package declaration that does not match its directory, an
internal import naming a declaration that does not exist, an `R.string.*` that is used but never
defined, a locale file missing a key or carrying an extra one, a manifest pointing at a class or
resource that is not there, and a repository that has stopped exec'ing a bundled payload.

```sh
python3 tools/static_check.py
```

It is not a compiler. Run a real build before shipping.

## Launcher icon

`art/logo.svg` is the source. The rendered PNGs are committed, so **a normal build needs no SVG
toolchain**. Only re-run this after changing the logo:

```sh
npm install @resvg/resvg-js     # once
tools/render_icons.sh
```

It emits legacy icons per density plus an adaptive foreground whose canvas is 108dp but whose
content is scaled to 66% and centred, so no launcher mask clips it. The script is reproducible: it
regenerates the committed PNGs byte-for-byte.
